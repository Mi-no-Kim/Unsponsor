# Phase 로드맵

> PH-1~PH-8을 2026-09-24에 [GitHub Milestone](https://github.com/Mi-no-Kim/Unsponsor/milestones)으로 옮겼다. 이제 GitHub Milestone이 원본이며, 이 문서는 이관 시점 스냅샷 겸 참고용으로 남는다.

Phase는 일정 이름이 아니라 프로젝트가 도달해야 하는 기능적 목표 상태다.

## 구성 원칙

Phase 1은 "규모와 무관하게 검증 가능한 기능"만으로 수집→처리→표시 파이프라인을 좁은 범위(제품 1~2개, 채널 3~5개 수준)로 끝까지 연결한다. 목적은 서비스로서의 완성도가 아니라 파이프라인이 실제로 이어지는지 조기에 검증하는 것이다. 여기서 쓰는 코드는 프로토타입이 아니라 실제 운영 코드이며, 이후 Phase에서는 같은 코드에 채널·영상 수를 늘려가는 방식으로 확장한다.

"데이터가 어느 정도 쌓여야 의미가 생기는 기능"(벡터 검색, 유사 제품 추천, 크리에이터 분석, 리뷰 트렌드 타임라인)은 Phase 1에 넣지 않고, 데이터가 쌓인 이후 Phase에 배치한다.

유튜브 채널 대상 선정은 별도 Phase가 아니라, 필요한 Phase 안에서 수행하는 활동으로 취급한다 (해당 Phase가 요구하는 만큼 채널을 늘리는 작업).

확장 기능(수치 스펙 비교표, 공식 데이터 포함 순위, 제품 이슈 조사, 비교 대상 제품 안내)은 데이터가 충분히 쌓인 뒤에 의미가 생겨 PH-4에서 다룬다. 네 기능 모두 feature.md에서 "검토 중"이라, PH-4를 시작할 때 만들지 여부를 먼저 확정한다.

## Phase 항목 형식 (GitHub Milestone과 동일)

Milestone **제목**은 `PH-N — 이름`, **설명**은 그 아래 내용을 그대로 붙여 넣는다.

```
## PH-N — 이름

**Goal**: 이 Phase가 끝났을 때 프로젝트가 도달해 있는 상태 (한 문장)

### 포함
### 포함 안 됨
### Done When        ← 체크리스트. 전부 체크되면 Milestone을 닫는다
### 실행 환경
### 관련 Feature
### 관련 Decision
### 진행하면서 정할 것 ← 이 Phase를 진행하면서 결정해야 하는 것. 없으면 "없음"
```

## PH-1 — 파이프라인 엔드투엔드 연결

**GitHub Milestone**: https://github.com/Mi-no-Kim/Unsponsor/milestone/1

**Goal**: 좁은 범위(제품 1~2개, 채널 3~5개, 영상 10~20개, 스마트폰+태블릿 일부)에서 수집부터 제품 페이지 표시까지 파이프라인이 실제로 끝까지 이어진다.

### 포함

- 채널 수동 등록, 영상 메타데이터 수집
- 자막 추출(1차 라이브러리, 2차 bs4 폴백) + STT 폴백(faster-whisper) (D-015)
- LLM ① 호출 — 제품 식별 + 삽입형 광고 구간 탐지 + 제품별 협찬 판별(설명란·`paidProductPlacementDetails`·자막을 근거로) — PH-1은 국내 채널만 다루므로 SponsorBlock 호출은 비활성 상태다 (D-016, D-036)
- LLM ② 호출 — 광고 구간을 뺀 자막으로 제품별 요약·카테고리 태깅 (ko/en 정리) (D-016)
- 협찬 포함/제외 두 버전 집계
- 리뷰의 개별 관찰을 속성(aspect) 단위로 정규화·누적하는 구조화 데이터 축적 — 문장 요약만으로는 여러 리뷰가 실제로 "쌓이지" 않기 때문에 필요 (D-024)
- 제품·속성 매칭 및 사람 승인 큐 관리 화면 — LLM이 추출한 마커가 애매하면 사람이 검토·승인하는 관리자 화면. 인증 필요 (D-020, D-024, D-025, D-026)
- 제품별 클린 리뷰 평가 화면
- 광고/협찬 뱃지
- 출처 표시 및 원본 영상 연결
- 데이터 커버리지 표시 (간단한 수준)

### 포함 안 됨

- 제품 간 비교 (PH-2)
- 자연어 속성 기반 벡터 검색, 유사 제품 추천, 크리에이터 분석 및 필터링, 리뷰 트렌드 타임라인 (PH-3)
- 대량 백필 운영 — 속도 조절, 실패율 모니터링 (PH-2)
- AWS 이전, 파이프라인 모니터링 대시보드 (PH-7)

### Done When

- [ ] 대상 영상 전부가 처리 큐의 마지막 단계(`summarize`)까지 끝났거나, 실패 사유가 남아 있다
- [ ] 승인 큐 화면에서 후보를 승인하면, 그 제품이 집계와 제품 페이지에 반영된다
- [ ] 매칭된 제품마다 협찬 포함/제외 집계가 있다
- [ ] 제품 페이지에서 종합 평가·속성별 장단점·협찬 뱃지·출처·커버리지가 보이고, 협찬 포함/제외 토글이 동작한다
- [ ] PH-1 Issue(I-001~I-010)가 모두 닫혀 있다

### 실행 환경

### 관련 Feature

### 관련 Decision

## PH-2 — 수집 규모 확장 (스마트폰+태블릿 완성)

**GitHub Milestone**: https://github.com/Mi-no-Kim/Unsponsor/milestone/2

**Goal**: 스마트폰+태블릿 카테고리의 채널 풀을 감당되는 만큼 넓혀 백필하고, 새 영상을 매일 자동으로 수집하는 상시 운영 상태가 된다. 제품 간 비교를 제공한다.

### 포함

- 채널 풀 확장 (스마트폰+태블릿) — 정해진 목표 규모 없이, 파이프라인과 API 쿼터가 감당되는 만큼 늘린다
- 백필 큐 실제 운영 (시간당 목표 속도, 실패율 모니터링, 속도 조정)
- 신규 영상 확인을 상시 운영 모드(일일 폴링)로 전환
- 제품명 매칭 3단계 전환 여부 판단 — PH-1부터 운영한 2단계 매칭(마커가 정확히 일치하면 바로 매칭, 나머지는 사람 승인 큐)을 늘어난 규모에서 돌려보고, 승인 큐 부담이 실제로 커졌으면 3단계(애매한 마커에 LLM 검수 추가)로 전환한다 (D-020)
- 제품 간 비교 — PH-1에서 이동. 이 시점엔 제품 수가 늘어 비교가 실제로 의미를 가짐. PH-1부터 쌓인 속성(aspect) 단위 구조화 데이터를 그대로 재사용한다 — 단순 요약 문장 나열은 제외 (D-024)
- 데이터 커버리지 표시 고도화 — PH-1부터 쌓인 속성 데이터를 재사용 (D-024)

### 포함 안 됨

- 검색·추천 (PH-3)
- 새 카테고리 (PH-5, PH-6)
- AWS 이전, 모니터링 대시보드 (PH-7)

### Done When

- [ ] 넓힌 채널 풀의 대상 영상이 모두 처리됐거나, 실패 영상 목록과 사유가 정리돼 있다
- [ ] 일일 폴링이 스케줄로 돌아, 새로 올라온 영상이 사람 손 없이 큐에 등록된다
- [ ] 백필 속도·실패율을 보고 조정한 결과가 남아 있다
- [ ] 제품명 매칭 3단계 전환 여부 판단이 `decisions.md`에 기록된다
- [ ] 제품 비교 화면에서 두 개 이상 제품을 속성 단위로 비교할 수 있다
- [ ] 제품 페이지의 커버리지가 속성별 근거 수까지 보여준다

### 실행 환경

로컬

### 관련 Feature

F-002, F-010(고도화)

### 관련 Decision

D-013, D-014, D-019, D-020, D-024

### 진행하면서 정할 것

- 제품 비교 화면 구성 — 어떤 속성을 어떤 기준으로 보여줄지 미정 (F-002)

## PH-3 — 검색·추천

**GitHub Milestone**: https://github.com/Mi-no-Kim/Unsponsor/milestone/3

**Goal**: PH-2까지 쌓인 데이터로 자연어 속성 검색, 유사 제품 추천, 크리에이터 분석, 리뷰 트렌드 타임라인을 제공한다.

### 포함

- Elasticsearch를 로컬 인프라(docker-compose)에 추가 — PH-1은 MySQL만 띄웠다
- 임베딩 생성 + Elasticsearch kNN 벡터 검색 — 협찬 포함/제외 두 벌 (D-017)
- 자연어 속성 기반 검색 화면
- 유사 제품 추천
- 크리에이터(리뷰어) 분석 — 협찬 비율·평가 성향, 신뢰도 지표, 채널 필터링. 통계는 `channels`와 분리된 별도 테이블 (D-021)
- 리뷰 트렌드 타임라인

### 포함 안 됨

- 확장 기능 — 수치 스펙 비교표, 공식 데이터 포함 순위, 제품 이슈 조사, 비교 대상 제품 안내 (PH-4)
- AWS 이전 (PH-7)

### Done When

- [ ] 자연어 질의로 속성 기반 검색 결과가 나온다
- [ ] 제품 페이지에 유사 제품 추천이 보이고, 협찬 포함/제외 전환에 따라 추천이 바뀐다
- [ ] 채널별 협찬 비율·평가 성향이 보이고, 채널로 필터링할 수 있다
- [ ] 제품 페이지에서 시간에 따른 평가 변화가 보인다

### 실행 환경

로컬

### 관련 Feature

F-006, F-007, F-008, F-009

### 관련 Decision

D-010, D-017, D-021, D-023

### 진행하면서 정할 것

- 임베딩 모델: text-embedding-3-small과 3-large 중 선택 (D-010)
- 랭킹·추천 설계 — 아직 초안 수준 (project-spec.md 오픈 이슈, F-008)
- 크리에이터 통계 테이블의 세부 필드 (D-021)

## PH-4 — 확장 기능

**GitHub Milestone**: https://github.com/Mi-no-Kim/Unsponsor/milestone/4

**Goal**: PH-3까지 쌓인 데이터와 새 데이터 소스를 활용해, 검색·추천 다음 단계의 부가 기능을 제공한다.

### 포함

네 기능 모두 `feature.md`에서 "검토 중"이다. PH-4를 시작할 때 각각 만들지 여부를 먼저 확정한다.

- 수치 스펙 비교표 (F-011) — 영상 화면 속 벤치마크·스펙표를 읽는 OCR 파이프라인이 새로 필요하다
- 공식 데이터 포함 순위 (F-012) — 공식 스펙·가격 데이터 연동이 필요하다. 랭킹 산정 방식은 유사 제품 추천(F-008, PH-3)과 같은 오픈 이슈다
- 제품 이슈 조사 (F-013) — 뉴스 등 외부 소스 연동이 필요하다. 비용·호출 제한·약관 검토 포함
- 비교 대상 제품 안내 (F-017) — PH-1부터 쌓인 비교 언급(`secondary` 리뷰)을 활용한다

### 포함 안 됨

- 새 카테고리 (PH-5, PH-6)
- AWS 이전 (PH-7)

### Done When

- [ ] 네 기능 각각 만들지 여부가 확정돼 `feature.md` 상태가 "확정" 또는 "폐기"로 바뀌어 있다
- [ ] 확정된 기능이 제품 페이지에서 동작한다

### 실행 환경

로컬

### 관련 Feature

F-011, F-012, F-013, F-017

### 관련 Decision

D-022, D-023, D-036

### 진행하면서 정할 것

- 네 기능 각각 만들지 여부
- F-011: OCR 도구와 읽을 대상(벤치마크 점수, 스펙표 등), 스펙을 저장할 카테고리 전용 테이블 (D-023)
- F-012: 공식 데이터 소스, 랭킹 산정 방식
- F-013: 뉴스 소스, 비용·호출 제한, 크롤링 범위와 약관
- F-017: 화면 구성, 협찬 제외 보기에서 협찬 영상의 비교 내용도 뺄지 (D-036)

## PH-7 — 운영 전환

**GitHub Milestone**: https://github.com/Mi-no-Kim/Unsponsor/milestone/7

**Goal**: 로컬에서 AWS 운영 환경으로 옮겨 사이트를 외부에 공개하고, 공개 운영에 필요한 장치(모니터링, Opt-out)를 갖춘다.

### 포함

- 로컬 → AWS 데이터 마이그레이션
- 파이프라인 모니터링 대시보드
- 프로덕션 비밀값 관리 방식 확정
- Docker 사용 여부(프로덕션 배포) 확정
- 투명성/Opt-out 페이지(F-015) — 사이트가 처음 외부에 공개되는 시점이라 이때 함께 둔다
- Opt-out 요청 처리 절차 — 요청받은 채널·영상의 데이터를 서비스에서 제외하고, 이후 다시 수집되지 않게 한다. 제외 방식(삭제 또는 제외 표시)은 착수 시 정한다. 삭제로 정하면 파괴적 데이터 작업이라 Protected Change다 (`rules.md` 1번, F-015, D-018)

### 포함 안 됨

- 해외 채널, 영어 화면 (PH-8)

### Done When

- [ ] AWS에서 사이트가 외부에서 접속된다
- [ ] 로컬 데이터가 AWS로 옮겨졌고, 테이블별 건수와 스키마가 일치함이 확인된다
- [ ] 모니터링 대시보드에서 일일 처리량·실패율·큐 잔량이 보인다
- [ ] Opt-out 안내가 사이트 하단에 있고, 요청 처리 절차가 문서로 남아 있다
- [ ] 배포 방식, 비밀값 관리 방식, Docker 사용 여부가 `decisions.md`에 기록된다

### 실행 환경

AWS

### 관련 Feature

F-014, F-015

### 관련 Decision

D-010, D-018, D-039 (RDS에서도 MySQL 8.4)

### 진행하면서 정할 것

- 배포 방식: EC2 직접 vs ECS/Fargate, RDS 사용 여부
- 비밀값 관리: AWS Secrets Manager vs Parameter Store
- Docker 사용 여부
- 데이터 마이그레이션 절차 (project-spec.md 오픈 이슈)
- Opt-out 제외 방식: 삭제 vs 제외 표시 (삭제면 Protected Change)

## PH-8 — 해외 채널 확장 + 영어 화면

**GitHub Milestone**: https://github.com/Mi-no-Kim/Unsponsor/milestone/8

**Goal**: 채널 풀과 영상 조사 범위를 해외 채널까지 넓히고, 사이트 영어 화면을 연다 (project-spec.md 핵심 목표 4번).

### 포함

- 해외 채널 풀 구성, 해외 영상까지 조사 범위 확장
- SponsorBlock 조건부 호출 활성화 — 국내(`language_code='ko'`)가 아닌 채널부터 호출 (D-016, D-021)
- 다국어 제품명 매칭 — project-spec.md 오픈 이슈 "제품명 정규화/매칭"의 다국어 부분
- 영어 화면(F-016) — PH-1부터 저장해 온 영어 데이터(D-028)를 이때부터 노출한다

### 포함 안 됨

- ko/en 외 표시 언어 — 표시 언어는 ko/en 2개로 고정 (F-016)

### Done When

- [ ] 해외 채널 영상이 파이프라인 끝까지 처리된다
- [ ] 해외 채널 영상에서 SponsorBlock 광고 구간이 `ad_segments`에 들어간다
- [ ] 다른 언어로 표기된 같은 제품이 하나의 제품으로 매칭된다
- [ ] 영어 화면에서 UI 문구와 리뷰 요약이 영어로 보인다

### 실행 환경

AWS

### 관련 Feature

F-016

### 관련 Decision

D-016, D-020, D-021, D-028

### 진행하면서 정할 것

- 해외 채널 선정 — D-027의 기준(구독자 규모, 활동성 등)을 해외 채널에 그대로 쓸지
- 영어 화면 구현 방식 (Next.js 다국어 라우팅 등)
