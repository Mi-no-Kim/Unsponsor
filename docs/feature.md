# Feature 목록

프로젝트가 사용자에게 제공하기로 한(또는 검토 중인) 기능을 기록하는 문서다. `workflow.md`의 Planning 계층에서 가장 상위 단위인 Feature에 해당한다 — Phase는 이 중 무엇을 "언제" 만들지 결정하고(`phase.md`), Issue/Work Unit은 그걸 어떻게 쪼개 구현할지를 다룬다.

## 무엇을 기록하는가

지금까지 기능적으로 언급된 것은 확정 여부와 무관하게 전부 기록한다 — 상태가 불확실한 것도 빼지 않고, 대신 `상태` 필드로 확실성을 표시한다. 빠뜨리는 것보다 "검토 중"으로라도 남겨두는 쪽이 나중에 다시 놓치지 않는다 (D-006).

Feature 항목은 "무엇을 제공하는가 / 왜 필요한가"만 적는다. 아직 정해지지 않은 구현 방법(데이터 저장·구조화 방식 등)은 결정된 것처럼 쓰지 않는다 — 미정이면 "참고"에 미정이라고 남긴다. 실제 구현 방법은 그게 필요해지는 시점(보통 Issue/Work Unit 설계 단계)에 따로 결정한다 (D-007).

## 항목 형식

```
## F-### — <기능 이름>

- 버전: v1
- 상태: 확정 / 검토 중 / 폐기
- 한 줄 요약: <핵심 한 줄>
- 설명: <무엇을, 왜, 사용자에게 어떤 가치를 주는지>
- 관련 Phase: <PH-### 또는 "미배정">
- 참고: <오픈 이슈, 전제 조건, 관련 다른 Feature/Decision 등 — 있으면>
```

`decisions.md`와 동일한 원칙: 기능 설명이나 범위가 나중에 바뀌면(번복되면) 같은 ID의 새 버전을 추가한다 (`F-003 v1` → `F-003 v2`). 이전 버전은 지우지 않고 해당 항목 아래 "이전 버전"으로 남긴다. 완전히 다른 기능이면 새 ID를 쓴다 — 비슷하다는 이유로 기존 ID에 억지로 합치지 않는다.

다만 버전은 사용자가 그 항목을 처음 검수한 이후의 변경부터 센다 (D-008). 항목을 막 작성한 직후 첫 검수 과정에서 나온 수정은 v1을 그대로 덮어쓰고 "이전 버전"을 남기지 않는다 — 아직 확인되지 않은 초안을 고치는 것이기 때문이다. 사용자가 그 항목에 이의 없이 넘어간 뒤에 다시 바뀌는 경우부터 새 버전으로 취급한다.

ID는 생성 순서대로 매기고, 폐기된 ID는 재사용하지 않는다.

## 상태 정의

- **확정** — 만들기로 확정된 기능. Phase 배정 여부와는 별개다 (확정됐지만 아직 어느 Phase인지 안 정해졌을 수 있다).
- **검토 중** — 만들지 여부나 구체적 형태가 아직 안 정해진 기능. 이 상태인 채로 그 기능의 Issue/Work Unit을 만들지 않는다 — 먼저 검토를 끝낸다.
- **폐기** — 더 이상 만들지 않기로 한 기능. project-spec.md에는 있었지만 이후 빠진 기능이면 여기 폐기로 남겨서 "왜 없어졌는지" 흔적을 남긴다.

## project-spec.md "기능"과의 관계

이 문서가 기능의 상세 원본이다. project-spec.md의 "기능" 섹션은 중복을 피하기 위해 각 F-### 항목을 가리키는 짧은 인덱스로 정리했다 — project-spec.md의 기존 내용을 들어내는 구조 변경이라(`rules.md` 6번) 사용자 확인을 먼저 받았고, 확인 후 실행했다.

## 기능 목록

### F-001 — 제품별 클린 리뷰 평가

- 버전: v1
- 상태: 확정
- 한 줄 요약: 여러 영상에서 뽑은 장단점을 제품 단위로 모아 보여준다
- 설명: 같은 제품을 다룬 여러 리뷰 영상에서 광고·협찬 구간을 제거하고 남은 장단점만 추출해, 제품 하나에 대한 종합 평가로 모아 보여준다. 장단점은 개별 관찰을 속성(aspect) 단위로 정규화·누적하는 구조화 데이터(`review_points`/`point_aspects`/`product_aspect_stats`, D-024)로 뒷받침되고, 문장 요약(`product_aggregates`)은 그 위에 얹히는 화면 표시용 레이어다. 이 서비스의 핵심 가치 제안이며 나머지 기능 대부분이 이 위에 얹힌다.
- 관련 Phase: PH-1
- 참고: PH-1 파이프라인 엔드투엔드 검증의 중심 기능. 속성 기반 구조화 데이터는 이 기능부터 쌓이기 시작하며, F-002·F-010(PH-2)은 이 시점부터 쌓인 데이터를 그대로 재사용한다 (D-024)

### F-002 — 제품 간 비교 (장단점 기반)

- 버전: v1
- 상태: 확정
- 한 줄 요약: 두 개 이상 제품의 장단점을 비교해서 보여준다
- 설명: 리뷰에서 뽑아낸 속성(배터리, 발열 등) 단위로 누적된 데이터를 바탕으로 제품 간 차이를 보여준다. 여기서 "장단점 기반"은 수치 스펙 비교(F-011, OCR로 뽑은 벤치마크·스펙표)와 구분하기 위한 표현이다. 제품별 요약 문장을 그냥 나란히 보여주는 방식(텍스트 나열)은 제외한다 — 그건 사실상 영상 요약을 그대로 옮기는 것뿐이라 "비교"라는 이름에 걸맞은 의미가 없다. 정확한 화면 구성(어떤 속성을 어떤 기준으로 강조할지 등)은 아직 정하지 않았다(D-007).
- 관련 Phase: PH-2
- 참고: 원래 PH-1 후보였으나, 초기에는 비교할 제품 수 자체가 적어 기능의 의미가 약해 PH-2(제품 수가 늘어난 시점)로 이동했다. 비교에 쓰이는 속성(aspect) 데이터 구조는 D-024 참고.

### F-003 — 광고/협찬 뱃지

- 버전: v2
- 상태: 확정
- 한 줄 요약: 협찬받은 제품의 리뷰에 뱃지를 붙인다 (제품과 무관한 중간 삽입 광고는 대상이 아니다)
- 설명: 리뷰 대상 제품 자체가 협찬받아 제작됐는지(`is_sponsored_review`)를 제품(리뷰)마다 판별해, 협찬받은 제품의 리뷰에 뱃지로 표시한다. 한 영상에 여러 제품이 나오면 실제로 협찬받은 제품에만 붙는다. 판별은 LLM이 설명란·유료 광고 포함 표시·자막을 근거로 한다 — 유료 광고 표시는 중간 광고만 있어도 켜지기 때문에 그것만으로 판별하지 않는다. 삽입형 중간 광고(리뷰 대상 제품과 무관한 VPN·앱 광고 등)는 이 기능의 대상이 아니다 — 그건 자막에서 조용히 제거되는 노이즈 구간일 뿐, 별도로 판별·뱃지·라벨링하지 않는다.
- 관련 Phase: PH-1
- 참고: 광고 유형 구분과 헷갈리는 지점은 project-spec.md "광고 유형 구분"·"두 광고 유형이 헷갈리는 지점" 섹션, D-016, D-036 참고.

  **이전 버전 (v1)**: 한 줄 요약 — 협찬 리뷰 판별 결과를 뱃지로 노출한다 (제품과 무관한 중간 삽입 광고는 대상이 아니다) / 설명 — 설명란 텍스트 파싱(+ `paidProductPlacementDetails` API 필드)으로 판별한 `is_sponsored_review`(리뷰 대상 제품 자체가 협찬받아 제작됐는지) 값을 리뷰 화면에 뱃지로 표시한다. SponsorBlock으로 감지하는 삽입형 중간 광고(리뷰 대상 제품과 무관한 VPN·앱 광고 등)는 이 기능의 대상이 아니다 — 그건 자막에서 조용히 제거되는 노이즈 구간일 뿐, 별도로 판별·뱃지·라벨링하지 않는다.

### F-004 — 협찬 리뷰 포함/제외 토글

- 버전: v1
- 상태: 확정
- 한 줄 요약: 제품 집계를 협찬 리뷰 포함/제외 두 가지 뷰로 전환해서 볼 수 있다
- 설명: 제품 단위 집계(장단점 요약 등)를 협찬 리뷰 포함/제외 두 버전으로 미리 계산해두고, 사용자가 화면에서 토글로 전환해 볼 수 있게 한다. 집계 로직 자체는 PH-1에 포함되어 있고, 화면 UI 노출 범위는 구현 시점에 조정될 수 있다.
- 관련 Phase: PH-1
- 참고: 집계 정책은 D-017 참고.

### F-005 — 출처 표시 및 원본 영상 연결

- 버전: v1
- 상태: 확정
- 한 줄 요약: 각 리뷰 항목에 채널명·영상 제목을 표시하고 원본 영상으로 연결한다
- 설명: 리뷰 항목마다 어느 채널·영상에서 나온 내용인지 명시하고, 유튜브 공식 임베드 플레이어 또는 아웃링크를 제공한다. 개별 제품의 상세 조회 화면에서 속성(aspect)별 평가 근거를 보여줄 때도 마찬가지로 원본 영상을 함께 보여준다(`review_points.quote`, D-024). 법적/정책 준수 사항(원작자 조회수 기여 구조를 화면상으로 드러내기)과 직접 연결된 기능이라 빠질 수 없다.
- 관련 Phase: PH-1
- 참고: D-018(저작권 리스크 완화 정책) 참고.

### F-006 — 크리에이터(리뷰어) 분석 및 필터링

- 버전: v1
- 상태: 확정
- 한 줄 요약: 채널 단위로 협찬 비율·평가 성향을 집계해 신뢰도 지표를 제공하고, 채널 필터링을 지원한다
- 설명: 채널별로 협찬 리뷰 비율, 평가 성향(후하게 주는 편인지 등)을 집계해 신뢰도 판단 지표로 제공하고, "이 채널만 보기" 필터를 지원한다. 데이터가 어느 정도 쌓여야 의미가 생기는 기능이라 PH-1에는 포함하지 않았다.
- 관련 Phase: PH-3

### F-007 — 자연어 속성 기반 검색

- 버전: v1
- 상태: 확정
- 한 줄 요약: "~한 기능이 장점인 제품" 같은 자연어 질의를 속성 태깅 + 벡터 검색으로 처리한다
- 설명: LLM 요약 출력에 카테고리 태그를 추가하고 Elasticsearch kNN 벡터 검색을 도입해, 자연어 질의를 속성 기반 검색으로 처리한다. 데이터 규모가 있어야 검색 결과의 의미가 생기는 기능이다.
- 관련 Phase: PH-3

### F-008 — 유사 제품 추천

- 버전: v1
- 상태: 확정
- 한 줄 요약: 장단점 유사도 기반으로 "비슷한 제품"을 추천한다
- 설명: F-007의 벡터 검색 인프라를 재사용해 장단점이 비슷한 제품을 추천한다.
- 관련 Phase: PH-3
- 참고: 추천에 쓰일 랭킹·순위 산정 방식은 project-spec.md 오픈 이슈로 아직 초안 수준(요소별 개별 랭킹 + 티어 표시 아이디어)이며 확정되지 않았다. 이 기능 자체는 확정이지만, 세부 랭킹 설계는 착수 전 별도로 다시 논의해야 한다.

### F-009 — 리뷰 트렌드 타임라인

- 버전: v1
- 상태: 확정
- 한 줄 요약: 같은 제품의 리뷰 평가가 시간에 따라 어떻게 변했는지 보여준다
- 설명: 기존에 쌓인 타임스탬프·요약 데이터를 재활용해 제품 평가의 시간에 따른 변화를 시각화한다. 신규 데이터 소스 없이 기존 파이프라인 데이터로 구현 가능하지만, 의미 있는 추이를 보여주려면 데이터가 어느 정도 쌓여야 해서 PH-3로 배치했다.
- 관련 Phase: PH-3

### F-010 — 데이터 커버리지 표시

- 버전: v1
- 상태: 확정
- 한 줄 요약: 지금 보는 집계가 몇 개 채널·영상을 근거로 하는지 투명하게 보여준다
- 설명: PH-1에서는 "몇 개 채널의 리뷰를 종합했는지, 자막 기반인지 STT 기반인지" 같은 단순 개수·소스 표시로 시작한다 — `videos`/`channels`의 기존 데이터만으로 바로 계산된다. PH-2에서는 F-001부터 쌓이는 속성(aspect) 단위 데이터(D-024)를 재활용해, "이 제품의 배터리 평가는 O개 채널·N건의 관찰을 근거로 한다"처럼 속성별 근거 커버리지까지 보여주는 방식으로 고도화한다 — 즉 PH-2의 "고도화"는 새 데이터 소스를 추가하는 게 아니라 F-001부터 이미 쌓인 구조화된 데이터를 재사용하는 것이다. 정확한 화면 구성은 미정(D-007).
- 관련 Phase: PH-1 (간단), PH-2 (고도화)
- 참고: PH-2 고도화는 F-001부터 쌓이는 속성 데이터 구조(D-024)에 의존한다.

### F-011 — 수치 스펙 비교표

- 버전: v1
- 상태: 검토 중
- 한 줄 요약: 화면 속 벤치마크·스펙 오버레이를 OCR로 읽어 수치 비교표로 제공한다
- 설명: 영상 화면에 나오는 벤치마크 점수나 스펙표를 OCR 파이프라인으로 추출해 수치 비교표를 만드는 기능. 신규 데이터 소스(OCR)와 별도 설계가 필요해 비용이 크고, project-spec.md에서도 "우선순위 검토 대상"으로 남아있다.
- 관련 Phase: PH-4
- 참고: 데이터가 충분히 쌓인 뒤 PH-4(확장 기능)에서 다룬다. 상태가 검토 중이라 PH-4를 시작할 때 만들지 여부를 먼저 확정한다.

### F-012 — 공식 데이터 포함 순위

- 버전: v1
- 상태: 검토 중
- 한 줄 요약: 유튜브 밖 공식 스펙·가격 데이터를 반영한 순위를 제공한다
- 설명: 공식 스펙·가격 데이터 소스 연동이 필요하고, 랭킹 산정 방식 자체가 아직 확정 전이다 (F-008과 같은 오픈 이슈 공유). 실현 가능성은 불확실하지만 되면 좋은 후보로 유지하고 있다.
- 관련 Phase: PH-4

### F-016 — 다국어 표시 (ko/en 고정)

- 버전: v1
- 상태: 확정
- 한 줄 요약: 원본 영상 언어와 무관하게, 사이트에 노출되는 언어(UI·요약 결과)는 ko/en 2개로 고정한다
- 설명: 채널 풀은 특정 언어·국가에 국한되지 않고 전세계로 확장하는 게 목표지만(project-spec.md 핵심 목표 4번), 사용자가 보는 화면(UI 문구, 리뷰 요약 결과)은 원본 영상의 언어와 무관하게 ko/en 2개로만 노출한다. 원본이 어떤 언어든 LLM 요약 단계에서 ko/en으로 정리해 내놓는 방식을 전제로 한다. 특정 화면 하나에 속한 기능이 아니라 모든 화면에 걸치는 cross-cutting 요구사항이다.
- 관련 Phase: PH-8
- 참고: 채널 풀이 한국어권 밖으로 확장되는 시점부터 실질적으로 검증되지만, 그 전에도 LLM 요약 단계 설계(F-001 등)에 전제로 반영되어야 한다. UI·요약을 다루는 다른 기능(F-001, F-002, F-007 등) 구현 시 함께 고려 필요. 영어 화면은 해외 채널 확장과 함께 PH-8에서 연다 — ko/en 요약 데이터는 PH-1부터 저장하지만(D-028) 영어 화면이 주 목표가 아니라, 그 전까지 영어 데이터가 화면에 쓰이지 않고 남는 것은 감수한다.

### F-017 — 비교 대상 제품 안내

- 버전: v1
- 상태: 검토 중
- 한 줄 요약: 제품 페이지에서, 그 제품을 리뷰하며 함께 비교된 다른 제품들과 어떤 차이점이 언급됐는지 정리해서 보여준다
- 설명: 리뷰 영상 중에는 주 리뷰 대상 제품 외에 다른 제품과 가볍게 비교하는 경우가 많다(예: A10 리뷰에서 A9·A10+ 언급). 이런 비교 언급은 그 제품 자체의 종합 평가(F-001)에는 반영하지 않지만(D-022), 데이터 자체는 버리지 않고 "이 제품이 비교 대상으로 어떤 제품들과 어떤 차이점으로 언급됐는지"를 제품 페이지에 정리해서 보여주는 별도 기능으로 활용한다.
- 관련 Phase: PH-4
- 참고: 구현 방법(요약 생성 방식, 화면 배치 등)은 아직 미정 (D-007). 근거는 D-022, 관련 기능은 F-001·F-002. 협찬 제외 보기에서 협찬 영상의 비교 내용도 뺄지는 기능을 확정할 때 정한다 (D-036). 상태가 검토 중이라 PH-4(확장 기능)를 시작할 때 만들지 여부를 먼저 확정한다.
